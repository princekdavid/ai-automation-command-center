# Development Rules

## Source of Truth
Repository documentation is the canonical source of project intent and implementation status.

## Mandatory Rules
1. Do not replace the existing automation framework.
2. Do not force a fixed framework or technology.
3. Discover before designing project-specific automation behavior.
4. Reuse existing project utilities and conventions where appropriate.
5. Do not generate skills without codebase understanding and validation.
6. Repository write access is not assumed; default to read-only discovery for connected projects.
7. Destructive or autonomous actions require explicit authorization.
8. AI suggestions are recommendations until validated.
9. Every meaningful implementation change must update implementation status.
10. Architectural deviations require a documented decision.
11. Keep the dashboard as the primary product; AI is an intelligence layer.
12. Avoid premature multi-agent complexity.

## Definition of Done
A meaningful feature is done only when implementation, tests/validation, documentation, status tracking, and relevant security considerations are addressed.
